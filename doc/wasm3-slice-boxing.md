# wasm3 slice boxing — design

## Goal

Represent a Go slice on `GOARCH=wasm3` as a single boxed WasmGC
struct rather than a flat `(data, len, cap)` tuple of wasm values.
Every slice value becomes one `(ref $go.slice.<T>)`, uniform with
how strings are already boxed as `$go.string`.

## Why

The flat representation makes a slice 3–4 correlated wasm values the
backend must keep together everywhere — spread across call params,
regrouped on return (`OpSelectN`), aligned through Phis, classified
anyref-vs-i64 by a fixed-point pass, and inlined into struct fields
and array elements. A large share of wasm3 backend complexity (the
anyref-propagation pass, the SelectN slice-component classifier,
Phi-of-components handling) exists only to manage that. Boxing
collapses a slice to one ref → one local → one value, and that
machinery can be **deleted, not just sidestepped**. It is therefore a
net simplification, in line with the project's correctness-and-
simplicity-first stage (performance work is deferred).

It also unifies the value model: strings are already
`$go.string = (struct (ref $go.bytes) i32 i32)`, so slices being flat
was an inconsistency. The end state is "aggregates are struct refs";
interfaces are the other flat aggregate and the same logic applies to
them later (out of scope here).

## The crux

Go's SSA models a slice as `(ptr, len, cap)` and computes slicing by
**pointer arithmetic**: `a[lo:hi]` lowers to `ptr = base + lo*elem`.
WasmGC has no interior pointers — you cannot point into the middle of
an array — so the data ref cannot be pre-offset. We must keep
`(array, off)` separate and address element i as
`array.get(data, off+i)`. The real work of this change is therefore
**rerouting every slice operation from pointer-arithmetic to
array+offset**, not merely wrapping three values in a struct. This is
also why an explicit offset field is required (the previous flat rep
had none, a latent subslicing gap), exactly as `$go.string` already
carries one.

## Representation

```
(type $go.array.<T> (array (mut T)))             ;; element backing
(type $go.slice.<T> (struct (field (ref $go.array.<T>))  ;; data
                            (field i32)                   ;; off
                            (field i32)                   ;; len
                            (field i32)))                 ;; cap
```

- One `$go.slice.<T>` per slice element type T, generated by the
  type collector (the same mechanism that already emits per-type
  array backings and other collected structs; cross-package indices
  are remapped by the existing `R_WASMTYPE` relocation).
- `[]byte` reuses `$go.bytes = (array (mut i8))` as its backing
  (shared with `string`); its header is `$go.slice.i8` /
  `$go.slice.byte`.

### Confirmed decisions

1. **cap is a stored field** (4 fields), not derived. This preserves
   Go-faithful semantics for 3-index slices `a[lo:hi:max]` (append
   isolation), at the cost of one i32 field. (Deriving cap from
   `array.len - off` would have lost the ability to represent a
   restricted capacity and silently changed `append` aliasing.)

2. **Typed data field**, not anyref — restores compile-time
   (validator) type checking and removes the per-access `ref.cast`.
   anyref is used **only at genuinely polymorphic sites**: interface
   boxing, reflection, and — *for now* — shape-instantiated generic
   slices (`func F[T any](s []T)` monomorphized by GC shape may lack a
   concrete element type). The generics fallback is a starting point,
   not necessarily the end state; revisit when generics support
   matures.

3. **nil slice = null ref.** `len`/`cap` special-case the null ref
   and return 0. `s == nil` is `ref.is_null`. (Chosen over a
   canonical shared empty struct.)

## De-risk (done, 2026-05-20)

Two pure-wat experiments under `wasmtime --preload` (gc +
function-references) confirmed the WasmGC mechanics, each with a
passing positive run and a trapping negative control:

1. A bare `(array (mut i8))` declared independently in two modules
   matches structurally across a cross-module `(ref ...)` import.
2. A **struct that references another type** —
   `$slice = (struct (ref $bytes) i32 i32 i32)` — likewise matches
   structurally cross-module, and `struct.get` of the typed-ref +
   i32 fields, `array.get_u` at `off+i`, and the `a[1:4]` offset/len
   slicing all produce the correct bytes.

So typed boxed slices passed by `(ref $go.slice.<T>)` work end to end,
including across the dynamically-linked host boundary (the prelude
emits each type as a singleton rec group, so structural equivalence
holds).

## Sequencing

A green-ladder checkpoint (empty / concat / map / iptr, plus the new
slice test below) follows each rung; commit per rung so any
regression is bisectable.

### Rung A — collector generates the types (additive)

Teach the type collector to emit `$go.slice.<T>` (and ensure the
`$go.array.<T>` backing exists) for each slice element type. Nothing
consumes them yet. Checkpoint: ladder green; `wasm-tools` shows the
new types present and unused.

### Rung B — atomic value-rep flip + op lowering (the big one)

Slices cannot be half-flat/half-boxed, so this rung is atomic. Bring
it up on a minimal internal slice ladder before the full ladder:

- `flatPrimitiveFields(TSLICE)` / `wasm3Fields` → one
  `(ref $go.slice.T)` field (was `(anyref, i64, i64)`).
- `wasm3ValueType` → a slice value is one ref local.
- Op lowering, in order: `OpSliceMake` → `struct.new`;
  `OpSlicePtr/Len/Cap` → `struct.get`; slicing (`OSLICE`/`OSLICE3`) →
  `struct.new` with `off' = off+lo`, `len' = hi-lo`, `cap'` from the
  3-index bound or `cap-lo` (the core offset work); element index →
  `array.get(data, off+i)` with the bound on `len`; `make([]T,n)`
  (`OpWasm3MakeSlice`) → `array.new` + `struct.new`; `append` grow
  path → new array + `struct.new`.
- nil → null ref; `len`/`cap` special-case null → 0.

Checkpoint: a new `slice-rep` test (nil, make, index, len/cap,
`a[lo:hi]`, `a[lo:hi:max]`, append-grow, range) prints ok; then the
full ladder green.

### Rung C — delete the dead multi-value machinery

With slices single-valued, remove the anyref-propagation fixed-point
pass, the `OpSelectN` slice-component classifier, and the
Phi-of-components handling. No-ops post-B; deleting them is the net
simplification. Checkpoint: ladder green after each deletion.

### Rung D — reconcile the fat-pointer path

`wasm3InteriorPtrByte` / `&s[i]` derives the array via `OpSlicePtr`
then indexes; with boxing it becomes `struct.get data` + `off+i`.
Small adjustment (may fold into B). Checkpoint: the iptr copy test
still prints ok.

### Then the host boundary unblocks

(`doc/wasm3-stage-j-plan.md` Piece 5 / the `runtime/wasm` package):
the wasmimport boundary passes a single typed `(ref $go.slice.byte)`;
write `runtime.wat`; convert `runtime/wasm` to `//go:wasmimport
go_runtime` signatures; `--preload` smoke test.

## Risk

Rung B is the atomic core and the most likely to redden the ladder
mid-flight (like the M2 cutover). Bring it up on the minimal slice
program first, then the full ladder.
